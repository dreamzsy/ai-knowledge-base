# AI 知识库 · 三 Agent PRD

> 版本：v0.1（高阶草案）
> 状态：draft · 含未决问题，待细化为任务
> 关联：CLAUDE.md（项目约束）、`.claude/agents/`（collector / analyzer / organizer 定义）

## 1. 背景与目标

把分散在社区前沿的 AI/LLM/Agent 技术动态，每日自动沉淀为结构化、可检索、可分发的知识条目。
本 PRD 定义三个 Agent 的职责边界与协作流程，**只定「做什么」与「边界」，不下沉实现细节**。

- 目标：每日产出一批经过摘要、标注、整理的 AI 热门项目知识条目。
- 非目标（本期不做）：多数据源（仅 GitHub Trending）、实时分发、人工审核 UI。

## 2. 总流程

```
每天 UTC 0:00 定时触发
   └─ collector ──→ analyzer ──→ organizer   （串行，单向）
        采集          标注          整理
```

- 触发：定时器，每天 UTC 0:00 一次。
- 编排：串行，上游产出是下游输入；任一环失败则链路中断（处理策略见 §5）。
- 状态流转：`collected → drafted → organized`。

## 3. Agent 职责

### 3.1 collector（采集）
- 抓取 GitHub Trending **Top 50**。
- 过滤出 **AI 相关**条目（LLM / Agent / 模型 / 框架等）。
- 仅存**客观事实字段**，落盘 `knowledge/raw/`。
- 边界：只采集、不分析；不写 `articles/`；raw 只追加不覆盖。

### 3.2 analyzer（分析）
- 读取 collector 产出的 raw 条目。
- 为**每条**打 **3 个维度的标签**（维度定义见 §6 待决）。
- 边界：只读 + 产出标注结果；不落盘最终条目（由 organizer 写）。

### 3.3 organizer（整理）
- 读取已标注条目。
- 整理成 **Markdown** 文档（结构 / 分组方式见 §6 待决）。
- 边界：只整理入库；不擅自分发、不越过校验发布。

## 4. 输入 / 输出概览

| 环节 | 输入 | 输出 | 落点 |
| --- | --- | --- | --- |
| collector | 数据源配置、时间窗口 | 原始条目（客观字段） | `knowledge/raw/` |
| analyzer | raw 条目 | 带 3 维标签的条目 | 传递给 organizer（见 §5 待决） |
| organizer | 已标注条目 | Markdown 知识文档 | `knowledge/articles/`（或 MD 目录，见 §6） |

## 5. 开放问题（待用 `to-issues` 细化为任务）

以下为本期**必须先拍板**的设计问题，逐条细化为可执行任务：

1. **上游失败、下游怎么办？**
   - collector 抓取失败 / 返回空时，analyzer、organizer 是跳过、等待、还是用上次结果？
   - 是否需要「部分成功」语义（50 条里成功 40 条也继续）？

2. **数据怎么传？文件 or 消息？**
   - Agent 间传递走**中间文件**（落盘 raw/ + 中间标注文件）还是**内存消息**（LangGraph state 直传）？
   - 取舍：文件可审计、可重跑；消息更快、但难追溯。

3. **重跑策略？**
   - 同一天重复触发时，是覆盖、跳过、还是生成新版本？
   - 幂等键如何定义（按日期？按条目 id？）。

4. **进度追踪？**
   - 如何观测「跑到哪一步、成功几条、失败几条」？
   - 失败是否告警、落日志还是落状态文件？

## 6. 待定义细节（次优先级）

- analyzer 的 **3 个标签维度**具体是什么（如：主题 / 价值分 / 成熟度？）。
- organizer 输出 MD 的**结构与分组**（按标签？按评分？单文件还是多文件？）。
- 「AI 相关」的**过滤判定规则**（关键词？topics？模型判断？）。
